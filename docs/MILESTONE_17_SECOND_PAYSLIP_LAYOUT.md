# Milestone 17 — a second documented payslip layout

Status: engineering implemented. Extends the Milestone 14 reader under [#35](https://github.com/obaonikoyi/taxprep-au/issues/35).

## User outcome

Until now the automatic reader understood exactly one layout, `PAYSLIP SUMMARY v1`, in which every figure sits on its own `Label: value` line. Any other payslip fell straight through to manual entry, so a user whose employer produces a normal tabular pay advice had to retype every amount.

This milestone adds a second documented layout, `PAY ADVICE v2`, and turns the reader into a small registry of layouts rather than one hard-coded parser.

This is still an explicit list of supported formats. It is **not** a claim that Xoba Paycheck reads arbitrary employer PDFs.

## Why the second layout is tabular

`PAYSLIP SUMMARY v1` is a convenient shape that real payroll systems rarely produce. Most Australian payslips lay figures out in a table, with a current-period column beside a cumulative year-to-date column:

```
Description            This pay      Year to date
Gross earnings         1,640.00         48,912.00
PAYG withholding         212.00          9,884.00
Other deductions          35.00            640.00
Net pay                1,393.00         38,388.00
Superannuation           188.60          5,624.00
```

That shape is the reason the reader now has to understand columns. It also carries the single most damaging mistake this reader could make: **reading the year-to-date column as if it were the current period**. Summing those across payslips would inflate a year's earnings several times over, and the resulting numbers would look entirely plausible.

## How the current-period column is chosen

1. The header row supplies the anchors. The reader finds the row containing both `This pay` and `Year to date` and records the horizontal centre of each phrase.
2. Every amount in a row is matched to the nearer anchor by the **centre** of its text. Centre, not left edge, because amounts in a table are right-aligned and their left edge moves with the number's width.
3. Only the current-period column is ever read. No code path extracts a year-to-date figure.

A field is left **blank** rather than guessed when:

- the header row is missing or its two columns are too close together to distinguish;
- a row offers only one amount, which could belong to either column; or
- the winning amount sits between the columns rather than under one.

A blank field asks the user a question. A wrong number silently becomes a total, so the reader prefers the question.

## What each layout supplies

| Field | `PAYSLIP SUMMARY v1` | `PAY ADVICE v2` |
|---|---|---|
| Employer | `Employer:` line | `Employer:` line |
| Period start/end | two separate lines | one `Pay period: … to …` line |
| Pay date | `Pay date:` line | `Payment date:` line |
| Gross, withheld, deductions, net, super | one labelled line each | current-period column of the amount table |

Dates in v2 use Australian `DD/MM/YYYY`, normalised through the existing `dateValue` parser. An absent `Superannuation` row leaves super unknown rather than recording zero, exactly as v1 does for a missing value.

## Traceability

Each record now stores the layout that read it. The review panel shows it beside the file name, and the downloaded report prints it per record instead of naming one parser for the whole session. Manual entries record no layout.

## Limits unchanged

One single-page PDF per file, selectable text, 2 MB per file, 20 files per batch, 100 records per session. Scans, photographs and undocumented layouts still require manual entry, and the error message now names both supported layouts so the user knows what the reader understands.

Nothing about confirmation changed: extracted values are candidates, every record still needs explicit user confirmation before it reaches a chart or total, and editing a figure invalidates that confirmation.

## Verification

Engineering checks only. These do not constitute payroll or tax approval.

- Three new fictional `PAY ADVICE v2` PDFs in `sample-data/payslips/advice-examples.json`, generated by `generate_v2.py`, carrying large unrelated year-to-date figures so a column mix-up produces obviously wrong totals rather than plausible ones.
- `payslipFormats.test.ts` drives those real PDF bytes through pdf.js and asserts the extracted figures and session totals, that no year-to-date figure appears in any field, that the current-period column wins even when the cumulative column holds the *smaller* number, and that a missing header, a lone amount or an amount between the columns each leave the field blank.
- Format detection is covered for both layouts, for an unsupported document, and for a file claiming to be both layouts at once.
- The hosted payslip smoke script uploads two v2 advices through the real file input, confirms them, checks the session totals are the sum of the current-period figures only, and checks the downloaded report names the layout and contains no year-to-date figure.
- The existing `PAYSLIP SUMMARY v1` suite is unchanged and still passes, so the first layout's behaviour is untouched.

## Not included

- Undocumented employer layouts, scans and photographs.
- Any inference of a figure the document does not state.
- Any change to tax treatment: the tax and refund gates in [#21](https://github.com/obaonikoyi/taxprep-au/issues/21) and [#28](https://github.com/obaonikoyi/taxprep-au/issues/28) remain exactly as they were.
